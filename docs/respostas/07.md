# Filas assíncronas no Laravel

## Resumo

Uma **fila** tira da requisição do usuário as tarefas demoradas ou que dependem de serviços externos. A aplicação registra a tarefa (um **Job**) e responde na hora; um processo separado (**worker**) executa o job em segundo plano.

## Como implementar

1. **Escolher o driver** no `.env`:
   - `QUEUE_CONNECTION=database` (tabela `jobs`, simples, já vem configurada no Laravel 12);
   - `redis` (mais rápido, recomendado em produção);
   - `sqs` (fila gerenciada da AWS).
2. **Criar o Job:**

```bash
php artisan make:job EnviarEmailConfirmacaoPedido
```

```php
class EnviarEmailConfirmacaoPedido implements ShouldQueue
{
    use Queueable;

    public int $tries = 3;

    public array $backoff = [10, 60, 300];

    public function __construct(public Pedido $pedido)
    {
    }

    public function handle(Mailer $mailer): void
    {
        $mailer->to($this->pedido->cliente->email)->send(new PedidoConfirmado($this->pedido));
    }

    public function failed(Throwable $erro): void
    {
        Log::error('Falha ao enviar confirmação', ['pedido' => $this->pedido->id, 'erro' => $erro->getMessage()]);
    }
}
```

3. **Despachar** onde a ação acontece:

```php
EnviarEmailConfirmacaoPedido::dispatch($pedido)->onQueue('emails');
```

4. **Rodar o worker:**

```bash
php artisan queue:work --queue=pagamentos,emails,default --tries=3
```

Em produção, o worker é mantido vivo por **Supervisor** ou **systemd** (ou pelo **Laravel Horizon**, com Redis, que também oferece painel de monitoramento).

5. **Tratar falhas:** jobs que esgotam as tentativas vão para `failed_jobs`; podem ser inspecionados e reprocessados (`queue:retry`).

## Boas práticas

- Jobs **idempotentes**: executar duas vezes não pode duplicar o efeito (cobrar duas vezes, enviar dois e-mails).
- Passar ids ou models serializados, não objetos enormes.
- Filas separadas por prioridade (`pagamentos` antes de `emails`).
- `ShouldBeUnique` para evitar jobs duplicados; *rate limiting* para APIs externas.
- Reiniciar os workers a cada deploy (`queue:restart`) para carregarem o código novo.
- Encadear etapas com `Bus::chain()` e processar lotes com `Bus::batch()`.

## Para que tipo de funcionalidade é útil

- **E-mails e notificações:** confirmação de pedido, recuperação de carrinho, push, WhatsApp.
- **Integrações externas:** gateway de pagamento, ERP, transportadoras, emissão de nota fiscal; o usuário não espera a API externa e as falhas são retentadas.
- **Processamento de arquivos:** redimensionar imagens de produtos, gerar thumbnails, importar planilhas, gerar PDFs e relatórios.
- **Tarefas em massa:** atualização de preços e estoque, disparo de campanhas, recálculo de índices de busca.
- **Webhooks recebidos:** responder 200 imediatamente e processar depois.
- **Relatórios e agregações:** atualizar tabelas de resumo fora do horário de pico.

Neste projeto, o upload de imagem (Ex. 10) é síncrono por ser uma imagem pequena. Numa versão maior, a geração de miniaturas em vários tamanhos iria para um job na fila.
