# Vue.js: ciclo de vida do componente e performance

## Resumo

Todo componente Vue passa por quatro fases: **criação**, **montagem**, **atualização** e **desmontagem**. Cada fase tem ganchos (hooks) em que podemos executar código. A performance da aplicação depende principalmente de duas coisas: **quantas vezes** o componente é renderizado de novo e **o que fica rodando** depois que ele sai da tela.

## As fases e os hooks (Composition API)

| Fase | Hooks | O que acontece | Uso típico |
|---|---|---|---|
| Criação | `setup()` (antes: `beforeCreate`/`created`) | Estado reativo, `computed` e `watch` são criados. Ainda não existe DOM. | Preparar estado, iniciar requisições que não dependem do DOM |
| Montagem | `onBeforeMount`, `onMounted` | O template vira DOM real e é inserido na página. | Acessar elementos (`ref`), medir tamanhos, integrar bibliotecas de DOM |
| Atualização | `onBeforeUpdate`, `onUpdated` | Um dado reativo mudou; o Vue gera o novo DOM virtual, compara com o anterior e aplica só as diferenças. | Raramente necessário; reagir a mudanças deve ser feito com `computed`/`watch` |
| Desmontagem | `onBeforeUnmount`, `onUnmounted` | O componente sai da tela. | Limpar timers, listeners, observers, conexões |

Com `<KeepAlive>` existem ainda `onActivated` e `onDeactivated`: o componente sai da tela, mas continua em memória.

## Como o ciclo de vida influencia a performance

1. **Re-renderização é o custo principal.** Cada mudança em um dado usado no template dispara a fase de atualização. Se o componente depende de dados que mudam muito, ou se um componente pai grande re-renderiza, todos os filhos que recebem props alteradas renderizam de novo.
2. **Trabalho pesado no lugar errado trava a tela.** Cálculos caros dentro do template ou em métodos rodam a cada renderização. Em `computed`, o resultado fica em cache até uma dependência mudar.
3. **Esquecer a desmontagem gera vazamento de memória.** `setInterval`, `addEventListener` em `window` ou WebSockets abertos em `onMounted` continuam vivos se não forem encerrados em `onUnmounted`. O componente sai, mas o trabalho continua e consome CPU e memória.
4. **Montar o que não aparece desperdiça tempo de carregamento.** Páginas e componentes que o usuário ainda não abriu não precisam ser baixados nem montados.

## Boas práticas

- `computed` para valores derivados (cache automático), `watch` só para efeitos colaterais.
- Limpar em `onUnmounted` tudo o que foi criado em `onMounted`.
- `v-show` para elementos que alternam muito (não desmonta); `v-if` para os que raramente aparecem (não monta à toa).
- `key` estável em listas `v-for`, para o Vue reaproveitar elementos em vez de recriá-los.
- `v-once` para conteúdo que nunca muda e `v-memo` para linhas de listas grandes que raramente mudam.
- `shallowRef`/`markRaw` para objetos grandes que não precisam de reatividade profunda.
- Rotas e componentes pesados carregados sob demanda (`() => import(...)`), divididos em arquivos separados pelo build.
- `<KeepAlive>` para telas que o usuário alterna com frequência, evitando montar tudo de novo.

## Como isso aparece neste projeto

- **Rotas sob demanda:** todas as páginas em `frontend/src/router/index.js` usam `() => import(...)`. O código do checkout, da administração e da página Teste Técnico só é baixado quando a rota é aberta.
- **Bibliotecas sob demanda:** o `faker-js` e o `cep-promise` são importados dentro das funções (`await import(...)`), só quando o usuário usa o recurso.
- **`computed` para totais:** a sacola (`stores/sacola.js`) calcula quantidade e subtotal com `computed`, recalculando só quando uma quantidade muda.
- **Limpeza na desmontagem:** o formulário de produto (`ProdutoFormView.vue`) libera a URL temporária da pré-visualização da imagem em `onBeforeUnmount`, evitando manter o arquivo em memória.
